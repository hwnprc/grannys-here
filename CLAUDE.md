## 1. Product overview

**Problem.** For people with early-to-mid stage dementia, memories aren't gone, they're hard to reach. Most memory apps are passive: the person must know what to search for. Family stories also disappear because nothing captures the places they happened in.

**Solution.** An ambient memory companion on the Vexo band. Granny tells stories naturally while wearing the band. AI turns each story into a structured memory linked to a place. When she is near that place, the band glows softly; one tap plays a gentle invitation and then her original voice telling the story. Family can open a 3D world of the place, generated by World Labs Atlas from family photos.

**Users.**
- Primary: a person with early-to-mid stage dementia (demo persona: "Granny").
- Secondary: family members who approve memories and revisit them together.

**Principles.**
- Invite, never quiz or correct.
- Family approves which memories can surface automatically. Sensitive memories never auto-trigger.
- Be transparent about listening (the band shows a solid blue light while the mic is on).
- Position as quality-of-life support, not treatment. Never claim it prevents or slows dementia.

## 2. MVP scope

**Must have (the demo loop)**
1. Capture a spoken story from the Vexo band → save original audio (WAV) + transcript.
2. Extract a structured memory with OpenAI (people, place, emotion, intro line, 3D scene prompt).
3. Generate a gentle spoken intro with ElevenLabs (pre-generated, not live).
4. Trigger: simulate "arriving" at a place (keyboard) → band glows warm amber.
5. Tap the band → play intro.mp3, then Granny's original audio.wav.
6. Open a web viewer showing the memory and the Atlas 3D world (video or splat).

**Should have**
- Family page listing memories with an "approved" status (static is fine).
- Atlas API call in code (live demo still uses a pre-generated world).

**Won't have today**
- Real GPS / phone app (simulate location on the laptop; say "in the product, the phone's GPS triggers this").
- Accounts, cloud database, caregiver dashboard beyond a mockup.

## 3. Demo flow (what judges see, ~2 min)

1. Someone wearing the band tells a 30-second story about a place (Golden Gate Park, Stow Lake).
2. The memory appears as structured data.
3. Press `p` ("arrive at the park") → band glows amber.
4. Tap the band → calm narrator: "You used to come here with your daughter every Sunday. Would you like to hear that story?" → Granny's real voice plays.
5. Browser opens the viewer → 3D world of the park plays while the story text shows.

- Do not guess library function names. Use only calls documented in `docs/api.md` or used in the examples.
- Rules:
  - Connect only to our own band number (passed as a CLI argument, e.g. `python3 capture.py 42`).

## 6. Data model: `memories/<id>/memory.json`

```json
{
  "id": "sunday-park",
  "title": "Sunday visits to the park",
  "summary": "Granny took her daughter to the lake in Golden Gate Park every Sunday.",
  "transcript": "...",
  "people": ["daughter"],
  "place_name": "Stow Lake, Golden Gate Park",
  "place_type": "park",
  "location_key": "park",
  "time_period": "1980s",
  "season": "autumn",
  "emotion": "warm, nostalgic",
  "sensitive": false,
  "approved": true,
  "intro_line": "You used to come here with your daughter every Sunday. Would you like to hear that story?",
  "scene_prompt": "A quiet lake in a city park on a sunny autumn afternoon...",
  "world_id": "dc2c65e4-...",
  "world_url": "https://marble.worldlabs.ai/world/dc2c65e4-...",
  "files": {
    "audio": "audio.wav",
    "intro": "intro.mp3",
    "pano": "pano.jpg",
    "world": "world.mp4"
  },
  "created_at": "2026-11-14T15:00:00-08:00"
}
```

`location_key` is a short key the demo trigger matches on (`park`, `kitchen`, `church`).

**The world API does not return a video.** `POST https://api.worldlabs.ai/marble/v1/worlds:generate`
(header `WLT-Api-Key`) is asynchronous: poll `/marble/v1/operations/{id}` for about
five minutes, then `response.assets` gives Gaussian splats (`splats.spz_urls`), a GLB
collider mesh, a panorama (`imagery.pano_url`), a thumbnail, and `world_marble_url`.
There is no mp4 anywhere in that payload.

`world_prompt.type` may be `text`, `image`, `multi-image` or `video`. The `image` type
takes `image_prompt` **and** an optional `text_prompt`, so send the reference photo and
`scene_prompt` together: the photo fixes the real geometry, the prompt carries season and
mood from her own words.

`image_prompt` is an **object**, not a string — sending base64 is rejected with HTTP 422:

```json
{"source": "uri", "uri": "https://..."}
{"source": "media_asset", "media_asset_id": "..."}
```

A local photo therefore needs three calls: `POST /marble/v1/media-assets:prepare_upload`
(`{file_name, kind: "image", extension}`) returns a media asset id and a signed URL, then
`PUT` the bytes to that URL with its `required_headers`, then generate with
`source: "media_asset"`. `atlas.py` does all three.

**marble.worldlabs.ai cannot be embedded** — it serves `X-Frame-Options: DENY` and
`frame-ancestors 'none'`, so an iframe renders an empty refusal box. The viewer therefore
shows `files.pano` inline and links out to `world_url` in a new tab. `files.world`
(a screen recording) still works as an offline fallback and takes over when there is no
panorama.

Generation needs a funded World Labs account — credits must be purchased before any key works.

## 7. Component requirements

### 7.1 `capture.py` (Person 1)
- Usage: `python3 capture.py <band_number> --id <memory_id>` (plus `--sim` if the kit supports it).
- Base it on `vexo-open-kit/examples/python/audio_to_text.py`.
- Record Granny's story from the band mic; save `audio.wav` and `transcript.txt` (Deepgram) into `memories/<id>/`.
- Use the band light to show state (listening vs saved) using documented calls only.
- Fallback: `--from-file path.wav` or `--transcript "text"` to create a memory without the band.

### 7.2 `process.py` (Person 2)
- Usage: `python3 process.py <memory_id>`.
- Read `transcript.txt`, call OpenAI with JSON output to fill the fields in section 6 (`title`, `summary`, `people`, `place_name`, `place_type`, `time_period`, `season`, `emotion`, `sensitive`, `intro_line`, `scene_prompt`).
  - `intro_line`: one gentle, second-person sentence ending with an invitation ("Would you like to hear that story?"). Never correct or test the person.
  - `sensitive`: true if the memory involves death, illness, conflict or loss.
  - `scene_prompt`: vivid visual description of the place (layout, objects, light, season, mood) for Atlas.
- Generate `intro.mp3` from `intro_line` with ElevenLabs (narrator voice, NOT a clone of Granny).
- Write `memory.json`. Default `approved: false` unless `--approve` is passed; set `location_key` via `--location park`.
- Optional: `--atlas` flag that sends `photos/` + `scene_prompt` to the Atlas API and saves the result. Check the Atlas developer docs for the exact endpoint; do not invent one. If unavailable, skip gracefully.
- Fallback: if any API fails, print a clear error and keep existing files.

### 7.3 `demo.py` (Person 1)
- Usage: `python3 demo.py <band_number>` (plus `--sim`).
- Connect to the band once and keep the connection for the whole demo.
- Keyboard input: `p` = arrive at park, `k` = kitchen, `q` = quit. (Map keys to `location_key`.)
- On arrival: find an **approved, non-sensitive** memory for that location.
  - None found → do nothing (light stays off).
  - Found → band glows **warm amber** → wait for a **tap** (timeout ~30 s → fade light, do nothing).
- On tap: play `intro.mp3`, then `audio.wav` (macOS: `afplay`; otherwise a cross-platform player), then open `http://localhost:8000/web/viewer.html?id=<id>` with `webbrowser`.
- Turn the light off at the end. Handle disconnects with a clear message.

### 7.4 `web/viewer.html` (Person 2 / Person 3)
- Static page, no build step. Reads `?id=` and fetches `../memories/<id>/memory.json`.
- Shows title, summary, people, place; plays `world.mp4` on loop, muted (or renders a splat with Spark, sparkjs.dev, if time).
- Button: "Hear the story again" plays `audio.wav`.
- Calm design: dark warm background, large readable text, no clutter. Works on a laptop screen for judging.

### 7.5 `web/family.html` (should have)
- Lists memories (hardcode the list of IDs or read a small `memories/index.json`).
- Shows title, place, sensitive flag and an "Approved" badge. Static mockup is acceptable.

## 10. Coding guidelines for Claude Code

- Python 3.9+. Keep scripts short, readable and runnable from the repo root.
- Add dependencies to `requirements.txt` (`bleak`, `openai`, `elevenlabs`, `python-dotenv`, `requests`, plus anything the kit examples need).
- Read the kit docs before writing band code; never edit files inside `vexo-open-kit/`.
- Prefer simple, working code over abstractions. No frameworks for the web pages.
- Every script prints clear status lines (e.g. `✓ saved transcript`, `✗ Deepgram error: ...`).
- Pre-generate anything slow (ElevenLabs audio, Atlas world) before the demo; the live loop should only play files.
- Ask before deleting or overwriting files in `memories/`.
